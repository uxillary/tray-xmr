# Website content roadmap

Content ships when it is useful, sourced and technically checked. Route ideas are themes, not a commitment to produce every possible keyword variation.

## P0 — Launch foundation

- Publish accurate product, current status and trust pages.
- Create the Learn, Guides, Troubleshooting and Tools hubs with clear in-development labels.
- Establish source/access-date notes, editorial review and correction practice.
- Configure the confirmed canonical origin before deployment; verify sitemap and robots output.

## P1 — Early growth

- Publish a sourced introduction to Monero mining and a clear hashrate explainer.
- **Shipped (M08):** a sourced Windows CPU mining setup guide that distinguishes standalone XMRig steps from Ember-specific capability. Recheck its upstream/version details before future edits.
- **Shipped (M11B):** the Huge Pages guide distinguishes privilege from allocation with a sourced signal table and dated XMRig version-scope note. Review Windows-specific instructions against current upstream documentation before future updates.
- Add contextual internal links and glossary definitions where they resolve real reader questions.

## P2 — Authority expansion

- Explain shares, jobs, pool difficulty, solo mining and P2Pool with protocol/pool sources.
- Cover MSR messages, rejected shares, low hashrate and pool connection issues.
- **Shipped (M11B):** a sourced Windows XMRig download/security-warning guide explains official-source checks, signed checksum-manifest limits and safe stop/verify decisions without advising security bypasses.
- **Shipped:** transparent electricity-cost and profitability calculators and the local-first XMRig log decoder. Keep bounds and assumptions visible; consider a unit converter only if a distinct reader need is established.
- Update pages as Monero, XMRig, Windows and Ember implementation details change.

## P3 — Original data and benchmarks

- Define opt-in collection, consent, privacy and deletion before any Ember benchmark dataset.
- Establish reproducible hardware test methods, software versions, profiles, ambient conditions and power measurement.
- Publish CPU profiles or comparisons only from traceable observations with sample sizes, caveats and raw methodology.
- Consider benchmark exploration and profitability scenarios only after data quality is demonstrable.
