# M13B — Competitor and complementary resource analysis

24 November 2026. Twelve resources assessed against Ember's existing 17-route collection. [Source inventory and research limits](m13b-search-intent-research.md#source-inventory); [consolidated decisions](m13b-content-growth-roadmap.md).

## Assessment scope

Read returned page text and inspected the **first screen at 390 × 844 CSS pixels** for each resource in the in-app browser. These are mobile presentation spot checks, not full-page reflow, physical-device, keyboard, screen-reader or calculation/export validation. No desktop comparison, performance audit, tracking/network audit or independent benchmark verification was performed. Browser viewport override was reset. Visual observations are bounded to the observed screen; advertising not visible there may exist elsewhere. No screenshot archive or competitor assets were copied into Ember.

Technical authority is separated from presentation. Official documents are primary technical anchors, while their performance examples can still be context-specific. Community-submitted benchmark records hosted by an official project are not standardized independent hardware tests. Competitor descriptions below reflect inspected material; they are not whole-site accuracy verdicts or market-share claims.

## Competitive implications

**Already served well:** live estimates, break-even output, official option lists, broad CPU tables, minimal-config generation and P2Pool introductions. Ember already has input provenance, worked arithmetic, an allocation signal table and contextual links. Do not schedule these as absent features.

**Plausible gaps:** a conservative connection/share/payout decision path; a finite source-versioned diagnostic reference connected to the existing decoder; whole-system measurement with a local two-configuration efficiency comparison; and small reproducible experiments that expose uncertainty. These are editorial judgments grounded in observed differences, not proofs of ranking potential.

**Credibility model:** link to authoritative docs at technical decisions, version each reference, label synthetic console examples, distinguish measured observations from models, and publish corrections. Benchmark snapshots must retain provenance, selection method and missing data. A clean chart with unverified numbers is not an improvement.

**Repeat visits and citations:** practical measurement/reference sheets can be reused when configurations change; a modest methods/data release can be cited for its specific conditions. No traffic, retention or backlink gain is forecast. Originality must come from the method and useful explanation; do not copy competitor prose, branding, code, screenshots or distinctive layouts.
