# D03D living workshop and information experience

## Audit and implementation plan

D03C already supplies a 320×144 scene with a 32×32 four-pose Squish, deterministic 4fps movement, visibility/reduced-motion gates, one cancellable timer, and asset fallbacks. Preserve those assets and scale. Add pixel-aligned crystal facets, a conduit and a small flywheel; strengthen tending/inspection gestures without result celebrations.

Rust supplies lifecycle, telemetry freshness, short/medium/long rate windows, sample timestamp, process identity, configured profile/threads, pool evidence, results, session time, startup timings and sanitized capture diagnostics. Sample timestamps permit deduplication; only fresh confirmed positive Mining may calibrate energy. No earnings, block discovery, measured CPU utilization or per-thread work is available. Configured lanes remain configuration evidence.

Implement a pure intensity reducer: collect distinct timestamped samples over at least 30 seconds, require a stable local baseline, freeze that baseline for the configuration/session, smooth relative rate and apply dwell/hysteresis. Missing calibration uses steady Mining. Stale/missing/zero/lifecycle changes disable responsiveness; reset calibration across gaps and configuration changes. Reduced motion remains static. Bound movement to 4–6fps and effects to a fixed small set.

The Stream already preserves backend order and a 256-row buffer. Replace its shared debug-like row layout with friendly Activity and compact Verbose presentations over those same events. Keep technical expansion, allowlist copied event fields, preserve reading position through mode/expansion updates, and always expose Return to latest while away.

Details currently includes all three rate windows, CPU configuration, pool endpoint/TLS/ping/failures/difficulty, huge pages, engine version, contribution accounting and measurement caveats. Retain them in aligned groups with concise explanations and explicit freshness. Startup diagnostics currently expands inline as lists. Move it into a bounded modal drawer with grouped stage/capture evidence and separately scrolling raw output; keep critical errors visible outside it. Preserve the backend's sanitized diagnostics-copy command.

Verify pure adapters and component structure, exercise actual DOM scrolling/mode switching/drawer focus and animation cleanup with development-only fixtures, inspect required viewport sizes/reduced motion/zoom, then run TypeScript, build, frontend tests, asset validation and diff checks. No real mining, backend contract changes, Rust changes or website changes.

## Implementation

- **Workshop:** preserve v3 artwork, manifests and the 32px character. Add pixel-aligned facet highlights, three conduit lights and a stepped flywheel at the existing machinery. Walking has a one-pixel footfall, tending alternates neutral/reach with a one-pixel lean, inspection holds the concerned pose. Starting approaches; Stopping/Stopped finish the bounded return. Idle remains attractive without simulated work. CSS effects only run for confirmed work after assets load, and stop when hidden, offscreen, reduced-motion or unmounted. Existing fallback artwork remains available.
- **Energy:** `workshopIntensity.mjs` is a pure reducer. At least 12 distinct samples spanning 30 seconds must all lie within 15% of their median; the baseline then freezes for that process/profile/thread configuration. Retain at most 64 calibration samples over 60 seconds. Clamp relative rate to 0.5–1.5, smooth with alpha 0.25, enter lively above 1.18/gentle below 0.82, leave lively below 1.08/gentle above 0.92, and require three successive candidate samples. Speeds are 4/5/6fps and effect cycles 4.8/3.6/2.4 seconds, with three conduit lights at every level. Missing/invalid timestamps never calibrate; repeated timestamps do not advance smoothing. Stale/unavailable/zero, a gap over five seconds, backwards timestamps, process/profile/thread changes and reduced motion reset comparison. Fresh positive Mining without comparison stays steady. A cancellable frontend evidence timeout marks displayed telemetry delayed after five seconds even if IPC stalls; it cannot change Rust lifecycle or Stop ownership. No saved baseline or synthetic telemetry exists.
- **Stream:** Activity uses human category labels, larger messages, distinct icons, severity and useful warning explanations. Verbose uses aligned timestamps/categories, technical source/kind, expandable structured fields and safe copying. Context is allowlisted by event kind; copying excludes arbitrary fields, session IDs, raw output, configuration and credentials. Failures report copy availability. The same supplied events retain backend order and the last-256 bound. A visible-row anchor preserves reading through layout/mode/buffer changes; Return to latest appears whenever away, with a count only when new rows arrive. The footer explicitly limits retention to this app run.
- **Details:** preserve rate windows, pool endpoint/ping/failures/TLS/algorithm/difficulty, engine/threads/huge pages, contribution accounting and measurement caveats. Use meaningful group icons with text headings, tabular numbers, explicit rate/time units, short difficulty/memory explanations and subdued unavailable values. Zero remains numeric. Last-reported freshness is explicit. Details has a bounded scroll area. CPU effort remains configured capacity, not measured utilization; connection nodes, clock, result counters and signal freshness remain visible.
- **Diagnostics:** replace inline lists with a named native modal drawer, an always-visible close control, Escape/focus return, grouped startup/capture evidence and an independently focusable bounded output region. Preserve both output-reader errors, all timings, all permitted sanitized notes, and the existing Rust-sanitized report command. Actual session errors also appear in Home, including last-reported errors during failed polling. The drawer does not alter workspace layout or Start/Stop semantics.

The development preview can explicitly enable a labelled **test-only event buffer** and choose 80/128/192 H/s fixture readings. It exercises the same App and pure adapter, without native commands. Production tree shaking removes the preview and its fixtures.

## Limitations and owner acceptance

The four-pose Squish sheet is retained, with better pose timing/translation rather than newly authored limbs or a complete directional walking cycle. The subtle effects and tiny character need owner art/motion acceptance at normal native size. There is deliberately no response to accepted shares, earnings or blocks.

**Actual 200% browser/native zoom is unverified.** Browser zoom shortcuts did not change the measured viewport, and native window capture failed during the attempted follow-up. The 410px layout is only the reflow-width equivalent of an 820px window at 200%; it is not reported as actual zoom acceptance. This pass inspected browser rendering, not a packaged WebView2 build. Native zoom, Windows 100/150/200% display scaling, full screen-reader/High Contrast use and packaged CPU/GPU profiling remain owner checks.

Owner review:

1. Open `npm run dev` → `/__living-core`. Review Ready, Starting, Mining, Stopping, Stopped, zero, stale, missing, failed and attention states. Confirm Squish stays tiny and the footfall/reach/inspection gestures and pixel machinery feel calm and recognisable. Check Start/Stop together in Home; never start real mining just for artwork review.
2. Leave Mining at fixture 128 H/s for at least 30 seconds, then choose 192 and 80 without replaying the state. Allow smoothing/dwell to settle. Confirm energy is restrained, with no results/earnings implication. Toggle reduced motion and verify the composed static scene.
3. Enable **Test-only event buffer**. Compare Activity/Verbose, expand a technical entry, copy the allowlisted context, read older entries and return to latest. Run the browser checks. Test Diagnostics in Error or enable Diagnostics mode in fixture Settings; verify raw scrolling, keyboard focus/Escape and prominent errors.
4. Review a packaged native build at required widths, short heights and actual 200% app zoom/display scaling. Use keyboard, screen reader and High Contrast, and profile idle/hidden animation cost. Explicitly accept or request refinements to artwork, motion and information hierarchy.
